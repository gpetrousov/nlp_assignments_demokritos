\subsection*{2}

Token-level metrics evaluate Named Entity Recognition (NER) by assessing each individual token, while entity-level metrics evaluate spans of tokens in a sentence. Token-level evaluation is simpler and lenient to mistakes, while entity-level evaluation is more strict and requires precise boundaries between entities.

In our situation, entity-level evaluation is preferred, since our task is to classify entities inside sentences. So, exact boundaries and strict identification might require tokens to span across many words (example "New York" instead of "New" and "York").

\subsection*{4}

\lstinline{align_label()} iterates through the sentence and assigns numeric IDs (\lstinline{word_ids}) to each token. Then, it iterates through those IDs to determine if a word was broken down into multiple subwords by the tokenizer. If it was, it only assigns a label (tag) for the first part (\lstinline{label_ids.append(label2id.get(labels[word_idx], -100))}) - ground truth. Ultimately, its role is to align human labeling (ground truth) with model tokenization so the inputs to the error function are aligned.

Subsequent subwords and special tokens (\lstinline{[CLS]}, \lstinline{[SEP]}, etc.) are assigned a target value of -100. PyTorch's loss function (\lstinline{CrossEntropyLoss}) will ignore this value and prevent these extra tokens from changing the model's weights during training.

The table with the specific labels for each token are available online\footnote{\url{https://huggingface.co/learn/llm-course/chapter7/2}}.

I wrote the following function to count the frozen and unfrozen model parameters.

\begin{lstlisting}[language=Python]
    # Count trainable and non-trainable parameters
    def count_model_params(model):
        nof_trainable = 0
        nof_frozen = 0
        for param in model.parameters():
            if param.requires_grad == True:
                nof_trainable += sum(p.numel() for p in param)
            elif param.requires_grad == False:
                nof_frozen += sum(p.numel() for p in param)
            else:
                print("Something went wrong!")
                break

        print(f"Trainable params: {nof_trainable}")
        print(f"Frozen params: {nof_frozen}")
\end{lstlisting}

Following is a reusable function I built to train any model later.

\begin{lstlisting}[language=Python]
# Training function
def train_model(model, train_loader, valid_loader):
    """ Will train only the classification head """
    EPOCHS = 3
    BATCH_SIZE = 8
    LR = 1e-5
    optimizer = optim.AdamW(filter(
        lambda p: p.requires_grad, model.parameters()), lr=LR)

    # train the model - SKIP if model loaded
    print('training the model')
    for epoch in range(EPOCHS):
        model.train()
        print(f'epoch {epoch + 1}/{EPOCHS}')
        for batch in tqdm(train_loader, desc=f"Training epoch {epoch + 1}"):
            batch = {k: v.to(device) for k, v in batch.items()}
            outputs = model(**batch)
            loss = outputs.loss

            optimizer.zero_grad()
            loss.backward()
            optimizer.step()

        # calculate performance on validation set
        Y_actual, Y_preds, y_true_tags, y_pred_tags = EvaluateModel(model, valid_loader)
        report_metrics(Y_actual, Y_preds, y_true_tags, y_pred_tags,
                      split_name=f"Validation (epoch {epoch + 1})")

    return Y_actual, Y_preds, y_true_tags, y_pred_tags
\end{lstlisting}

\subsection*{8}

Following are the small changes I made in order to repeat task 1 using the \lstinline{RoBERTa} model. First, I imported the library which contains the models for token classification.

\begin{lstlisting}[language=Python]
# Import the model for token classification
from transformers import RobertaForTokenClassification
\end{lstlisting}

Next, I loaded the model with the classification head as the final layer and set \lstinline{add_prefix_space=True}\footnote{\url{https://huggingface.co/docs/transformers/en/model_doc/roberta\#transformers.RobertaTokenizer.example}} for the tokenizer. The last variable instructs the tokenizer to not treat spaces as part of tokens.

\begin{lstlisting}[language=Python]
# Load the model with classification head
model = RobertaForTokenClassification.from_pretrained(
    "roberta-base",
    num_labels=num_labels,
    id2label=id2label,
    label2id=label2id
)

# Layer layer from model architecture:
# (classifier): Linear(in_features=768, out_features=9, bias=True)

# Load tokenizer
tokenizer = RobertaTokenizer.from_pretrained(
    "roberta-base",
    add_prefix_space=True
    )
\end{lstlisting}

For training and evaluation I used the same code from task 1.

\lstinline{RoBERTa} has been trained on significantly more data than \lstinline{BERT} thus is an improved model. This fact is reflected on following evaluation metrics:
